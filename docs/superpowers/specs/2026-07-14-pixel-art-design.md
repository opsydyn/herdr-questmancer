# herdr-webmaster pixel-art design

## Intent

The cybercafe should feel like a carefully authored 90s block-art scene, not a
dashboard decorated with random glyphs. Agents must be recognizable from their
silhouette before the user reads a label. Their movement must explain real
state, and their surrounding workstation must expose useful activity.

The supplied IT Crowd block-art reference establishes the fidelity bar:
exaggerated proportions, strong silhouettes, large flat colour regions, a few
signature facial details, and restrained highlights. It is inspiration for a
visual grammar only. Webmaster must not reproduce those characters, costumes,
logos, poses, or composition. Every shipped persona and asset is original.

## Rendering strategy

Unicode mode uses a logical pixel canvas packed into terminal cells with
half-block characters. A terminal cell can represent two vertical pixels:

| top pixel | bottom pixel | glyph | style |
|---|---|---|---|
| empty | empty | space | panel background |
| colour | empty | `▀` | foreground = top |
| empty | colour | `▄` | foreground = bottom |
| colour A | colour B | `▀` | foreground = A, background = B |
| same colour | same colour | `█` | foreground = colour |

The compositor resolves transparent pixels against the panel background before
packing cells. Widgets receive already-packed Ratatui lines and do not know how
persona components were assembled.

The canonical palette uses xterm-256 indices, not copied game or television
palettes and not truecolour-only shades. Each persona receives six to eight
colours: skin, hair, top, bottom, shoes, accent, highlight, and shadow. The room
uses a separate warm amber, nicotine-beige, phosphor-green, and dark-brown
palette. ANSI-16 mode maps those roles to the closest readable terminal colour.

ASCII mode is a semantic fallback, not a damaged pixel renderer. It uses small
labelled silhouettes and explicit state symbols such as `[!]`, `[~]`, `[x]`,
and `[+]`.

Terminal image protocols and raster assets remain out of scope for v0.1.

## Persona grammar

A stable `PersonaKey` seeds independent traits rather than selecting one fixed
character. Trait combination is deterministic and remains stable across pane
changes and plugin restarts.

```rust
struct PersonaAppearance {
    proportions: Proportions,
    head_shape: HeadShape,
    skin_tone: PaletteRole,
    hair: HairShape,
    hair_tone: PaletteRole,
    face_detail: FaceDetail,
    top: OutfitTop,
    bottom: OutfitBottom,
    shoes: Shoes,
    accessory: Accessory,
    desk_prop: DeskProp,
    accent: PaletteRole,
}
```

Traits are combined freely. Hair, clothing, body proportion, skin tone, and
accessories must not be proxies for agent capability, status, or gender. The
generator rejects combinations that destroy the silhouette or cause adjacent
regions to collapse into one colour.

Every persona must have at least four recognition anchors:

1. a distinct outer silhouette;
2. one face or hair marker;
3. one large outfit colour block;
4. one accessory or desk prop.

Example original anchors include an angular fringe and huge headphones, a
compact figure with round glasses and a striped jumper, a tall figure with a
high collar and pager, or a broad figure with a visor and novelty mug.

Handles and appearance share a seed but are generated by separate functions,
so changing handle vocabulary cannot silently change the art.

## Two authored representations

### Cafe sprite

The cafe uses a dedicated seated pose on an 8-10 by 12 logical-pixel canvas,
which packs into at most 10 columns by 6 terminal rows. It is not a scaled-down
profile sprite.

The minimum 28x10-cell workstation allocates:

- one title/name row;
- six scene rows for the CRT, seated agent, desk, and chair;
- one state row;
- borders and responsive padding.

Wider workstations add a second monitor, desk prop, modem lights, paper, or a
status placard. They never increase the amount of required information.

### Full-body profile

The selected-agent profile uses a separately composed 16 by 32 logical-pixel
canvas, displayed as 16 columns by 16 terminal rows. Its neutral pose exposes
the complete silhouette, clothing, shoes, and accessory. Status appears beside
the character as text and an icon; profile identity is not distorted by a
permanent state animation.

At 120 columns or wider, the figure sits beside agent details. At 80-119
columns, it occupies the left side of the selected-agent panel. Below 80
columns, the user can switch between details and the full-body card. Tiny
terminals use a compact bust or ASCII identity card.

## State theatre

State changes posture and workstation activity without changing identity.

| state | seated agent | workstation | explicit label |
|---|---|---|---|
| working | leans forward; two-frame hand alternation | cursor/scanline and modem lights | `BUILDING` |
| blocked | turns outward and raises one hand | CRT shows a high-contrast help card | `HELP!` |
| done unseen | chair kicks back for a one-shot celebration | eight-frame confetti burst, then update badge | `UPDATE READY` |
| done seen | relaxed seated pose | stable completion badge | `DONE` |
| idle | slouched or hands off keyboard | deterministic screensaver | `IDLE` |
| exited | no person | empty chair and broken CRT mark | `BROKEN LINK` |
| focused | pose unchanged | desk lamp turns on and border gains a marker | `LIVE` |
| disconnected | last pose remains | room-level reconnect overlay | `RECONNECTING` |

Blocked state always has the raised-hand silhouette, `HELP!` text, and an inbox
item. It never depends on red alone. Exited state uses both absence and a broken
link marker. Focus uses a lamp, border marker, and label.

## Animation timing

Animation derives from an injected monotonic clock. Renderers never own timers
or mutate domain state.

- Working: four deterministic frames at 6 fps.
- Blocked: a two-frame beacon at 2 fps; the raised hand remains static.
- Done transition: eight frames at 8 fps, lasting one second exactly.
- Idle screensaver: one frame per second.
- Exited and done-seen: event-driven static rendering.
- Room ambience: at most 2 fps and only while something visible changes.

`motion = "reduced"` removes CRT flicker, beacon flashing, and confetti motion;
it keeps a single strong pose and update badge. `motion = "none"` renders only
event-driven static frames. Animation never triggers output reads or state
persistence.

## Composition and visual hierarchy

The cafe is a room first and a card grid second. A shared floor line, wall
colour, cable runs, and counter make adjacent workstations feel connected.
Workstation borders remain subtle so agents and CRTs dominate.

Information order is:

1. pose and state silhouette;
2. selection/focus marker;
3. agent handle;
4. explicit state and elapsed time;
5. optional custom status and decorative props.

Selection never replaces agent state. The selected workstation gains a double
corner, brighter desk lamp, and cursor marker. The state pose and label remain
unchanged.

Decorations earn their space:

- modem lights show recent output activity;
- paper shows bounded accumulated activity, not changed-file count in v0.1;
- a ringing counter phone indicates old blocked attention;
- a screensaver means idle;
- confetti means a new completion transition, never permanent done state.

## Component boundaries

The visual implementation should use the following focused units:

```text
src/ui/pixel/
  canvas.rs       logical pixels, clipping, and transparent composition
  pack.rs         two-pixel-to-terminal-cell packing
  palette.rs      semantic xterm-256 and ANSI-16 palettes

src/ui/persona/
  appearance.rs   deterministic appearance traits
  cafe_sprite.rs  seated pose composition
  profile.rs      full-body composition
  state_pose.rs   state-specific pose and transition frames

src/ui/widgets/
  agent_crt.rs    workstation structure and useful CRT content
  profile_card.rs full-body identity plus textual details
```

The domain owns persona identity and state. Pixel modules know nothing about
Herdr. Widgets receive an appearance, presence, transition effect, clock frame,
and rectangular area.

## Failure and fallback behaviour

- Clipping is deliberate; drawing outside a logical canvas is ignored.
- Zero-sized Ratatui areas produce no cells and never panic.
- Invalid or low-contrast generated palettes fall back to a known safe palette.
- Unknown presence renders the neutral pose with `UNKNOWN`.
- Narrow cafe layouts replace the room with a vertical list of compact CRT and
  bust icons.
- ASCII mode remains fully actionable and carries the same labels and keys.

## Verification

Tests operate below and above the terminal packing boundary.

1. Pixel canvas tests cover clipping, transparency, and every top/bottom packing
   combination.
2. Persona tests prove stable generation, trait diversity, and safe palette
   fallback.
3. Logical-sprite golden tests cover each pose without terminal escape codes.
4. Ratatui `TestBackend` tests cover cafe and profile layouts at 160x50, 120x30,
   80x24, and tiny sizes.
5. Clock-controlled tests prove one-shot confetti ends and reduced/no-motion
   modes are static.
6. ASCII and ANSI-16 snapshots prove state remains legible without Unicode,
   truecolour, or colour alone.

Golden fixtures must not contain volatile handles, timestamps, or random seeds.
Each fixture declares its persona seed and clock instant.

## Acceptance criteria

The visual slice is ready when:

1. three generated personas are distinguishable from silhouette alone;
2. the same persona is recognizable in seated and full-body representations;
3. working, blocked, done-unseen, idle, and exited are identifiable without
   reading colour;
4. blocked and exited remain unambiguous in ASCII mode;
5. done confetti stops after one second;
6. 80x24 remains actionable and zero-sized areas do not panic;
7. no supplied reference character, costume, logo, or composition is copied;
8. idle rendering performs no periodic work when nothing visible changes.
