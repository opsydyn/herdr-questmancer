## 1. Preference durability

Use one cooperative writer per configured Questmancer profile. Acquire the
lease before reading saved preferences and keep it through final worker shutdown.
A second pane can display saved state, but preference changes require a writer.
Distinguish queued incidental state from a confirmed explicit save. Keep the
previous choice on a failed write and distinguish a replacement whose durability
could not be confirmed. A launch without a state directory reports that it cannot
save preferences. See [the profile writer decision](../adr/0008-profile-writer.md).

The proof starts with two startups sharing a directory. It also exercises the
normal character picker, failed writes and restart through the persistence
worker with a temporary profile. No live pane is needed.

The second-launch test reproduced both panes receiving write paths. It now
verifies a read-only second launch and a successful fresh launch after the
first releases its lease. Three character-picker checks cover a real save and
readback, a failed file write that preserves the previous character and bytes,
and cancellation or a changed adventurer identity. The full gate follows the
initial UX changes.

## 2. Party name

The first Ledger page offers `p` to edit the local profile's party name.
`Enter` saves, `Esc` returns to the Ledger, and `Ctrl-U` clears the draft
so saving restores the default. The name belongs to the whole roster and
does not depend on the current workspace or membership.

The focused test uses production input, rendering and the save worker. It
checks the compact Ledger, cancel, saved name in both rooms after startup
reload, and restore default.

## 3. Party status

The selected name, presence and primary shortcut share a single status row.
The row also carries the counsel count and sits above diagnostics, so a
Chronicle notice cannot hide it. Fitted rooms use their existing reserved row.
The fallback reserves two terminal rows at 24 columns by 16 rows or larger.

The regression test reproduced a compact fallback missing the primary action.
It now checks both rooms with all five actors, visible identity, counsel count
and an independent Chronicle diagnostic. Existing fitted-room and profile hit
mapping checks passed with this change.

## 4. Herdr status explanation

Use `i` on the selected adventurer. Questmancer asks Herdr for one
`agent.explain` response, then confirms the pane's identity and live status.
The parchment shows the live status, the screen estimate when it differs,
and whether session evidence supports Chronicle observations. Closing the
parchment, changing the connection or observing a new status invalidates the
explanation.

An isolated Herdr 0.9.5 run reported a pane as needing counsel while its screen
detector fell back to resting. Herdr also advanced the pane revision while the
identity and live status stayed the same. Socket fixtures accept this response
and refuse a replacement terminal or changed live status. The rendering
fixture hides the explanation after a new status observation.

## 5–7. Room integration

The [comparison images and review prompts](../reviews/2026-11-18-core-ux/README.md)
cover the three approved studies. Both rooms use the new materials in fitted
and ANSI rendering. The Delve mist is lighter so the Unknown adventurer stays
legible against the new flagstones. Storybook keeps the original materials for
comparison.

The fitted Delve gives a fresh Working observation up to 1.5 seconds of movement
toward the adventurer's usual station. The feet follow clear floor and the route
reserves space beside the rest of the party. Rat Royalty uses the study's two
authored strides. Other classes keep their current working frames. The actor's
hit region follows its position. Reduced and Still motion, retained facts at
reconnect, compact crowds and seats without room for a route show the actor at
its station. The walk adds no extra frame deadline after arrival.

## 8. Counsel and spoils cues

In fitted rooms, a counsel marker can sit beside its adventurer when a neighbour
occupies the space above. The roster and fitted-room spoils glint uses a visible
side gutter clear of other actors. The effect requests frames only when there is
space to show it, and it ends at the existing three-second boundary.

## 9–10. Herdr capabilities

The bundled Herdr 0.9.5 schema includes `notification.show` and `agent.wait`.
A disposable server returned `shown: false` with reason `disabled` for a silent
counsel notification. Any future opt-in notification should respect that
delivery result and avoid duplicating Herdr's own blocked-state alerts.
[Herdr notification API](https://herdr.dev/tui/docs/socket-api/#raw-methods)

On the same server, a bounded watch for `blocked` returned the synthetic
adventurer when its status changed from `working` to `blocked`. In a second run,
the watched report was released and another adventurer reported `blocked` on
the same pane. The original wait returned `agent_not_running`. A future watch
action can reuse that occupant-pinned wait for an explicit, cancellable request.
[Herdr waiting API](https://herdr.dev/tui/docs/socket-api/#waiting-for-state)
